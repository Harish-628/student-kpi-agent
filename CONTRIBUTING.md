# Contributing to NeuralKPI

Thank you for your interest in contributing to the Student KPI Management System! Following these guidelines helps ensure a smooth process for everyone.

## Code of Conduct

Please be respectful and professional in all interactions within this project.

## How to Contribute

1.  **Fork the Repository:** Create your own fork of the project.
2.  **Create a Branch:** Create a feature branch for your changes (`git checkout -b feature/amazing-feature`).
3.  **Make Changes:** Implement your feature or fix.
4.  **Lint Your Code:** Ensure your code follows the PEP 8 style guide. We use `ruff` for linting.
    ```bash
    ruff check .
    ```
5.  **Commit Changes:** Write clear, concise commit messages.
6.  **Push to Branch:** Push your changes to your fork.
7.  **Open a Pull Request:** Submit a PR to the `main` branch of the original repository.

## Code Style

-   Follow [PEP 8](https://www.python.org/dev/peps/pep-0008/) for Python code.
-   Use descriptive variable and function names.
-   Add docstrings to classes and functions where appropriate.
-   Ensure all new features include relevant tests or verification steps.

## Pull Request Process

-   Provide a clear description of the changes in your PR.
-   Link any related issues.
-   Ensure the CI pipeline passes before requesting a review.
-   At least one maintainer must approve the PR before it can be merged.
